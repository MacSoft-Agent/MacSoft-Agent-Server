MacSoft Agent Server CORS 与桌面快捷方式修复报告
日期：2026-07-17

一、要解决的问题

1. MacSoft Client 开发 Renderer 从以下 Origin 请求 LAN Server 时：
   - http://127.0.0.1:5173
   - http://127.0.0.1:5174
   - http://localhost:5173
   - http://localhost:5174

   Server 虽然实际返回 200，但 FastAPI CORSMiddleware 的
   allow_origins=[] 不允许任何带 Origin 的浏览器请求，因此响应没有
   Access-Control-Allow-Origin，Client 最终显示 Failed to fetch。

2. 安装后的公共桌面快捷方式当前名为 MacSoft Agent.lnk，要求改为：
   MacSoft Server.lnk。

3. 此前完成但尚未同步到 .9 的 Server chat 回复持久化顺序修复，需要与
   本次 CORS 修复一起进入现有 .9 staging 和新安装包。

二、分析与最小修复思路

1. CORS 仅增加四个明确的 loopback 开发 Origin。
   - 不使用 allow_origins=["*"]。
   - 不增加宽泛 app:// 正则。
   - 不增加 null Origin。
   - 保留 allow_credentials=False。
   - 保留现有 GET、POST、PATCH、DELETE、OPTIONS methods。
   - 保留现有 Content-Type、Authorization、X-Device-Id、
     X-Client-Version、X-MacSoft-Client-Capabilities、Accept headers。
   - 打包版 file:// Client 不发送 Origin 的原行为不受影响。

2. 快捷方式仅修改公共桌面名称，不进行产品级重命名。
   以下内容保持 MacSoft Agent：
   - 产品名
   - 安装目录
   - ProgramData 目录
   - Windows 服务名 MacSoftAgentHost
   - 开始菜单目录和快捷方式
   - 卸载注册项

3. 为兼容覆盖安装：
   - 创建 MacSoft Server.lnk 前删除旧 MacSoft Agent.lnk。
   - 安装失败回滚同时删除新旧两个桌面快捷方式。
   - 正常卸载同时删除新旧两个桌面快捷方式。

4. 不修改 pairing、token、/api/client/pair、/api/client/me、
   session ownership、SSE 字段、AutoCount、Hermes、SOUL、模型或认证逻辑。

三、源码和安装器修改

1. C:\MacSoft-Agent\server\macsoft\server.py
   - 新增 CLIENT_CORS_ORIGINS。
   - CORSMiddleware 改为 allow_origins=CLIENT_CORS_ORIGINS。

2. C:\MacSoft-Agent\server\tests\test_cors.py
   - 新增 /health CORS 测试。
   - 新增 /api/client/me OPTIONS preflight 测试。
   - 新增未列入白名单的 Origin 不被反射测试。

3. C:\MacSoft-Agent\packaging\installer\MacSoft-Agent.nsi
   - 新增 DESKTOP_SHORTCUT_NAME "MacSoft Server"。
   - 公共桌面创建 MacSoft Server.lnk。
   - 覆盖安装、失败回滚和卸载清理旧 MacSoft Agent.lnk。
   - 回滚和卸载同时清理 MacSoft Server.lnk。

4. C:\MacSoft-Agent\product_runtime\tests\test_packaging_contract.py
   - 新增桌面快捷方式名称与兼容清理合同测试。
