# Supplier Discrepancy and CN Follow-Up

When PO and supplier document differ, first show the exact difference and ask whether the agreed terms/PO changed, the delivery is partial, or the supplier document is wrong. Do not assign blame from one source alone.

CN is not the default discrepancy route. Use these branches:

- PO contains old/incorrect agreed data: preview and approve a PO correction, read it back, then return to normal receiving.
- Supplier invoice overcharges the company: treat this as the CN candidate and obtain supplier correction/commitment.
- Supplier invoice undercharges the company: explain the difference and ask for the approved business treatment; do not automatically request CN.
- Quantity, Item, tax, or delivery differences: explain the exact facts and ask whether the PO, supplier document, or delivery circumstances are authoritative.

If the user rejects the current PO and no accepted correction exists, keep the Case pending. Do not proceed to PI merely because the document can technically be posted.

## Supplier follow-up

If the user decides supplier correction is needed, prepare but do not send:

- resolved trusted recipient/contact;
- company/Case/PO/invoice reference;
- concise discrepancy facts;
- requested correction or CN;
- exact message text and purpose.

Show all of these and obtain approval. Supplier-contact mapping is not approval authority. Send using the same approved text; material edits require new approval. Persist sent result and waiting state.

The user may contact the supplier personally. If the user instead authorizes the Agent to contact or follow up, use the existing WhatsApp transport after the exact message is approved. A supplier promise to issue a CN keeps the Case waiting; it is not the CN itself.

## CN/corrected document arrives

Resolve it to the Case using trusted source, supplier, invoice/PO, references, amount/lines, and evidence identity. When ambiguous, ask instead of attaching it to the first waiting Case.

Register and extract the document, show its material correction to the user, and ask whether this exact version is accepted. A forwarded CN is not automatically accepted.

## Separate decisions

1. User accepts/rejects the supplier document version.
2. If accepted, separately ask whether any AutoCount CN status/action should occur.
3. Retrieve the live command/schema; execute only after a second approval.

If no verified CN status command/mapping exists, record the accepted CN and clearly mark AutoCount CN status as manual/connector-blocked. Never reinterpret it as a Purchase Return without approved business mapping.

When an accepted correction establishes the valid PO/invoice basis, resume Batch/Expiry review and final PI preparation. Keep unresolved financial differences pending rather than hiding them in the PI.

If the supplier never responds or sends another incorrect version, keep the Case pending and notify/escalate according to configuration.
